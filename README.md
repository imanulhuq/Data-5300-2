# Data-5300-2: Multimodal Phishing & Cognitive Fatigue Dataset

This repository hosts the experimental data and stimulus materials accompanying the **PHANTOM** study (*PHishing under Acute Neural and Task-Overload Models*) — a controlled, IRB-approved investigation of how cognitive fatigue affects users' ability to detect phishing websites under simultaneous EEG and eye-tracking measurement.

The dataset supports the behavioral, oculomotor, and neurophysiological analyses reported in the accompanying manuscript (under review). It comprises per-participant raw and processed signals, the full phishing stimulus set used in the within-subject pre-/post-fatigue protocol, and the aggregated analysis tables generated by the published pipeline.

---

## 1. Study Overview

PHANTOM uses a within-subject design in which each participant completes:

1. A **pre-fatigue phishing-detection block** (20 trials, real vs. fake website classification).
2. A **32-minute incongruent Stroop task** as a validated cognitive-fatigue induction.
3. A **post-fatigue phishing-detection block** (20 new trials).
4. **Cyber Operations Stress Survey (COSS)** administered both pre- and post-session (seven subscales: mental, physical, temporal, performance, effort, frustration, fatigue).

Throughout the session, participants are recorded with:

- **B-Alert X10** wireless EEG (10-channel subset of the 10–20 montage, 256 Hz, impedance < 10 kΩ).
- **GazePoint GP3** eye tracker (60 Hz, ≤ 0.5° accuracy, 5-point calibration).
- **High-precision behavioral logs** (per-trial accuracy, reaction time, stimulus identifier, ground-truth label, Unix timestamp).

A total of **37 participants** completed the full behavioral protocol; the per-participant ZIP files in this repository correspond to the per-trial logs and synchronized physiological streams collected during their sessions. Participants are pseudonymized with non-recoverable IDs of the form `P-5301`–`P-5337`.

## 3. Per-Participant ZIP Files (`01. P-5301.zip` … `37. P-5337.zip`)

Each ZIP contains the complete data for one participant's session. Although exact internal file naming may vary slightly across early vs. late participants (the data collection pipeline was iterated during the study), the canonical contents are:

| File | Description |
|---|---|
| `phishing_session1.csv` | Per-trial log for the **pre-fatigue** phishing block. Columns: trial index, stimulus ID, ground-truth class (real / fake-easy / fake-difficult), participant choice (Real / Fake), reaction time (ms), Unix timestamp. |
| `phishing_session2.csv` | Per-trial log for the **post-fatigue** phishing block. Same schema as session 1. |
| `stroop_log.csv` | Trial-by-trial Stroop responses across the 32-minute fatigue induction. Columns: trial index, presented word, presented color, response, correctness flag, reaction time (ms), timestamp. |
| `coss_pre.csv` / `coss_post.csv` | Self-reported workload at baseline and post-session, across the seven COSS subscales (each on a 1–21 scale). |
| `eeg_*.csv` (B-Alert export) | Raw 10-channel EEG samples at 256 Hz, plus per-second cognitive-state probability features (engagement, workload, drowsiness) emitted by the B-Alert acquisition suite. |
| `gaze_*.csv` (GP3 export) | Per-sample gaze coordinates, fixation/saccade events, and pupil-diameter measurements at 60 Hz. |
| `events.csv` (where present) | Synchronization markers aligning EEG, gaze, and behavioral streams to a common Unix timeline. |

> Approximately **26 of the 37 participants** met strict usability and temporal-alignment criteria (clean EEG impedance, successful gaze calibration sustained across both blocks, complete behavioral logs) and constitute the *fusion-ready* subset used for multimodal EEG ↔ eye-tracking analyses in the manuscript. Single-modality analyses use larger modality-specific subsets. The full **n = 37** sample is used for all behavioral and COSS analyses.

## 4. Stimulus Folders (`cmVhbA/`, `ZWFzeQ/`, `ZGlmZmljdWx0/`)

The phishing-detection task draws from a pool of **57 full-page website screenshots** spanning **19 brands × 3 versions** (real, fake-easy, fake-difficult), selected to span the e-commerce, financial, social-media, and cloud-storage categories most frequently impersonated in the wild.

| Folder | Decoded Name | Class | Count | Description |
|---|---|---|---|---|
| `cmVhbA/` | `real` | Legitimate | 19 | Authentic login/landing pages from major brands (e.g., Apple, Bank of America, Chase, Dropbox, Facebook, PayPal). |
| `ZWFzeQ/` | `easy` | Phishing — low difficulty | 19 | Counterfeits with **overt** deceptive cues (URL anomalies, gross visual mismatches, missing SSL indicators). |
| `ZGlmZmljdWx0/` | `difficult` | Phishing — high difficulty | 19 | Counterfeits with **subtle** deceptive cues (look-alike domains, near-pixel-perfect logos, plausible HTTPS framing). |

A bundled archive of all 57 screenshots is also provided as `websites.zip` for convenience.

## 5. Analysis CSV Files

The repository ships seven aggregated CSV tables generated by the analysis pipeline. Each `*_results.csv` is a machine-friendly export; each `*_readable.csv` is the same data with descriptive column headers for human inspection.

### 5.1 Behavioral Tables

**`behavioral_analysis_results.csv` / `behavioral_analysis_readable.csv`** — Per-participant behavioral metrics across the two phishing blocks.

| Column | Description |
|---|---|
| `participant_id` | Pseudonymous participant ID (e.g., `P-5301`). |
| `pre_correct_rate` / `post_correct_rate` | Proportion of correctly classified trials in each block. |
| `delta_correct_rate` | Post − Pre accuracy change (negative = decline). |
| `pre_mean_duration_s` / `post_mean_duration_s` | Mean reaction time (seconds). |
| `delta_duration_s` | Post − Pre duration change. |
| `pre_time_up_rate` / `post_time_up_rate` | Proportion of trials with no response within the 6-second window. |

These columns reproduce the per-participant tables in the manuscript appendix.

**`behavioral_coss_results.csv` / `behavioral_coss_readable.csv`** — Pre- and post-session COSS scores across the seven subscales (mental, physical, temporal, performance, effort, frustration, fatigue), one row per participant per administration.

### 5.2 Visual-Stimulus Characterization

**`website_text_image_heaviness_scores.csv`** — Per-screenshot visual scoring along the text↔image spectrum (`0` = text-heavy, `1` = image-heavy), computed via four independent computer-vision algorithms:

1. **Edge density** (Sobel/Canny edge ratio — text proxy)
2. **Whitespace ratio** (high-intensity-pixel proportion — visual richness)
3. **Shannon entropy** (grayscale information complexity)
4. **Color variance** (RGB cross-channel variance)

Each algorithm output is min-max normalized to `[0, 1]`, direction-aligned, and averaged into a final **Hybrid Score**.

**`website_text_image_heaviness_summary_by_class.csv`** — Mean ± SD Hybrid Score per stimulus class (real, fake-easy, fake-difficult). All three classes cluster around Hybrid ≈ 0.54, confirming there is **no class-level visual confound** — i.e., participants cannot solve the task by exploiting a systematic real-vs-fake visual difference.

### 5.3 Trial-Level Merge

**`visual_behavioral_merged.csv`** — Trial-level join between behavioral outcomes and per-stimulus visual scores. One row per trial; supports the trial-level visual↔behavioral correlation analyses in the manuscript (no statistically robust visual predictor of detection accuracy survives correction; see §6 of the paper).

**`visual_site_summary.csv`** — Per-website pre-/post-fatigue accuracy, Δ accuracy, and trial counts. Supports the per-website breakdown reported in the appendix (all 19 sites show accuracy decline; outliers Skype, Twitter, Dropbox, PayPal discussed in the paper).

## 6. How to Reproduce the Manuscript Figures

The CSV tables in this repository are exactly the inputs consumed by the analysis pipeline that produces the manuscript's behavioral and COSS results. To reproduce:

1. Unzip the per-participant archives into a single working directory.
2. Run the behavioral pipeline against `behavioral_analysis_results.csv` to regenerate Tables 4 and 8 of the manuscript (paired t-tests, per-participant breakdown).
3. Run the COSS pipeline against `behavioral_coss_results.csv` for the subjective-workload analyses.
4. For multimodal EEG ↔ eye-tracking analyses, restrict to the fusion-ready 26-participant subset and apply the participant-wise train/test split documented in the manuscript (`§5: Results`).

The analysis scripts themselves are maintained in a separate repository (linked from the manuscript) to keep this dataset repository focused on data.

## 7. Data Provenance & Quality Notes

- **Sample size.** 37 participants completed the full behavioral protocol. Two participants are omitted from the per-participant behavioral tables (Tables A.10 / A.11 of the manuscript) due to a logging-format mismatch but are retained in all group-level statistics.
- **Modality availability.** EEG and eye-tracking availability varied across participants due to channel dropouts, gaze-calibration failures, or partial recordings. The fusion-ready subset (n = 26) is determined by strict usability and temporal-alignment criteria.
- **Synchronization.** All physiological streams share a Unix timestamp basis, enabling millisecond-level alignment to the per-trial behavioral logs.
- **Pseudonymization.** Participant IDs are non-recoverable. No demographic, contact, or consent-form information is included in any of the per-participant ZIPs.

## 8. Ethics, IRB Approval, and Responsible Use

The PHANTOM study was conducted under a full **Institutional Review Board (IRB)-approved protocol**. All participants provided written informed consent, were compensated for their time, and could withdraw at any point without penalty. Cognitive fatigue was induced using the validated, low-risk incongruent Stroop paradigm; no procedure in this study posed physical risk.

By downloading or using any portion of this repository, you agree to the following terms:

1. **Academic use only.** Data and stimuli are released to support replication, secondary analysis, and methods research in cognitive security, usable security, and human factors.
